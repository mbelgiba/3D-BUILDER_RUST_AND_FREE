# Архитектура проекта

```text
Браузер (TypeScript + Three.js)
  ├─ загрузка изображения ─────────> Axum: проверка и сохранение
  ├─ запуск/опрос задачи ──────────> Rust запускает локальный TripoSR (Python)
  ├─ загрузка и показ GLB <──────── Rust отдаёт локальный файл модели
  └─ запрос PPM-рендера ──────────> Rust-трассировщик лучей ──> P3 PPM
```

Axum раздаёт собранный интерфейс из `frontend/dist` и API-маршруты `/api`. В режиме разработки Vite обслуживает TypeScript-приложение и перенаправляет API-запросы на порт 3000. Tokio запускает HTTP-сервер и локальный процесс TripoSR. Модель требует отдельного Python-окружения и загружает веса при первом запросе.

Создание профиля и вход выполняются на Rust-сервере. Пароли хешируются Argon2, хеши хранятся в игнорируемом Git файле `data/accounts.json`. Сессия использует случайный HttpOnly cookie; для API загрузки, генерации и рендера требуется действующая сессия. Серверная сессия живёт до 30 дней и сбрасывается при перезапуске. Модели и настройки редактора остаются в браузере: GLB-файлы библиотека хранит в IndexedDB, поэтому они не синхронизируются через сервер между разными устройствами.

Рендерер — отдельный модуль на Rust. Для каждого пикселя строится луч камеры. Ближайшее пересечение с примитивом задаёт нормаль и цвет поверхности. Точечный источник даёт ламбертовское рассеянное освещение, а дополнительный луч проверяет наличие жёсткой тени. Результат кодируется как текстовое изображение P3 PPM.

Модель GLB отображает и редактирует только Three.js в браузере. Трассировщик лучей пока не пересекает треугольники произвольной сетки и не рендерит импортированные GLB.
