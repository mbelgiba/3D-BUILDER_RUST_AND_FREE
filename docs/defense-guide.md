# Руководство к защите проекта

## Краткое описание

RT Studio — учебное веб-приложение. Оно проверяет загруженное изображение, запускает локальную модель TripoSR для приблизительной реконструкции, показывает GLB через Three.js и рендерит четыре сцены из примитивов собственным трассировщиком лучей на Rust.

## Архитектура и путь данных

Браузер отправляет JPEG или PNG серверу Axum. Rust проверяет данные и сохраняет изображение под случайным именем, затем запускает локальный TripoSR как Python-процесс. Браузер опрашивает Rust о состоянии задачи. После завершения Three.js загружает локальный GLB. Отдельно запрос рендера выбирает одну из встроенных сцен Rust и скачивает P3 PPM. Трассировщик не рендерит произвольные модели AI.

## Ответственность компонентов

- **Rust:** HTTP API, проверка изображений, запуск локальной модели, векторная математика, пересечения, свет, тени и PPM.
- **TripoSR:** локальная открытая модель для приблизительной реконструкции объекта по одному изображению.
- **Three.js:** показ GLB в браузере, камера, трансформации, материалы и свет интерактивного предпросмотра.
- **Трассировщик лучей:** отдельный рендер четырёх заданных сцен из примитивов, а не GLB-моделей.

## Основные алгоритмы

- Вектор — три числа. Скалярное произведение измеряет взаимную ориентацию; векторное строит перпендикуляр; нормализация задаёт длину вектора равной единице.
- Луч записывается как `origin + t * direction`. Функции пересечения примитивов находят допустимые неотрицательные значения `t`.
- Для сферы решается квадратное уравнение; для куба пересекаются интервалы по трём осям; для плоскости используется отношение расстояния к скалярному произведению; для цилиндра проверяются боковая поверхность и крышки.
- Ламбертовская яркость равна `max(0, normal · direction_to_light)`. Фоновый свет добавляет базовую яркость. Луч тени проверяет, закрывает ли другой объект точечный источник.
- P3 PPM — текстовый формат: маркер `P3`, ширина, высота, максимальный канал `255`, затем значения RGB. Rust ограничивает значения каналов перед записью.

## Где искать реализацию

- `src/math/vector.rs`: `Vec3::dot`, `Vec3::cross`, `Vec3::normalized` — операции с векторами.
- `src/math/ray.rs`: `Ray::at` вычисляет точку на луче.
- `src/geometry/sphere.rs`, `cube.rs`, `plane.rs`, `cylinder.rs`: математика пересечений и вычисление нормалей.
- `src/renderer/camera.rs`: `Camera::ray_for_pixel` строит первичный луч пикселя.
- `src/renderer/scene.rs`: `Scene::trace` ищет ближайшее пересечение, проверяет тень и рассчитывает цвет.
- `src/renderer/light.rs`: `shade` применяет ламбертовский и фоновый свет.
- `src/renderer/ppm.rs`: `encode` кодирует пиксели в P3.
- `src/api/upload.rs`: `inspect_image` проверяет формат, размеры и декодирование.
- `src/api/generation.rs`: `create_generation` создаёт AI-задачу; `get_generation` возвращает её статус.
- `frontend/src/main.ts`: `loadGeneratedModel` загружает GLB и размещает его в кадре Three.js.

## Вопросы и короткие ответы

1. **Что делает проект?** Связывает API преобразования изображения в 3D, просмотрщик Three.js и трассировщик лучей на Rust.
2. **AI точно восстанавливает предмет?** Нет. Один снимок не показывает скрытые стороны, поэтому результат приблизительный.
3. **За что отвечает Rust?** Проверяет загрузки, вызывает AI-сервис и реализует трассировщик примитивов с выдачей PPM.
4. **Что делает Three.js?** Показывает GLB и управляет камерой и сценой на стороне браузера.
5. **Что такое луч?** Начальная точка и направление; параметр `t` задаёт расстояние вдоль него.
6. **Зачем нормализовать направления?** Единичная длина упрощает сравнение расстояний и расчёты света.
7. **Где используется скалярное произведение?** Оно измеряет взаимную ориентацию векторов; освещение Ламберта использует его для яркости.
8. **Где используется векторное произведение?** Оно создаёт перпендикулярный вектор, например для базиса камеры.
9. **Как находится пересечение со сферой?** Подстановка луча в уравнение сферы даёт квадратное уравнение.
10. **Что такое касание сферы?** Луч касается её в одной точке; дискриминант квадратного уравнения равен нулю.
11. **Как находится пересечение с кубом?** Метод интервалов проверяет пересечение луча с коробкой по трём осям.
12. **Зачем обрабатывать параллельные лучи для куба отдельно?** Деление на ноль недопустимо; луч либо лежит в соответствующем интервале, либо промахивается.
13. **Как находится пересечение с плоскостью?** Подписанное расстояние делится на скалярное произведение направления луча и нормали.
14. **Как ориентирован цилиндр?** Его центральная ось параллельна Y; проверяются боковая часть и обе крышки.
15. **Что такое ламбертовское освещение?** Рассеянная яркость пропорциональна косинусу угла между нормалью и направлением на источник.
16. **Что такое фоновый свет?** Небольшая базовая яркость, сохраняющая видимость поверхностей без прямого света.
17. **Как проверяются тени?** Луч от поверхности к источнику проверяет, есть ли между ними другой объект.
18. **Зачем смещать начало луча тени?** Небольшое смещение по нормали не даёт лучу сразу пересечь ту же поверхность из-за округления чисел.
19. **Что означает P3?** Текстовый вариант формата Portable Pixmap с RGB-каналами.
20. **Может ли трассировщик рендерить AI-модель?** Пока нет; доступны четыре встроенные сцены с примитивами.
21. **Нужен ли ключ AI?** Нет. TripoSR запускается локально; нужны Python-зависимости и веса модели.
22. **Как проверяется файл?** Сервер определяет реальный JPEG/PNG, декодирует данные и ограничивает размер файла и количество пикселей.
23. **Почему используется опрос статуса?** Генерация выполняется отдельным процессом и может занять время; браузер проверяет состояние задачи на сервере.
24. **Что произойдёт, если TripoSR не установлен?** Сервер сообщит об этом; демонстрационная сцена и трассировщик останутся доступны.

## Практические задания

1. Измените центр сферы и посмотрите, как меняется силуэт.
2. Добавьте вторую сферу и проверьте, что закрашивается ближайшее пересечение.
3. Переместите источник света и сравните рассеянное освещение.
4. Измените интенсивность фонового света и выполните рендер снова.
5. Переместите камеру и сравните третью и четвёртую сцены.
6. Добавьте тест для луча, начинающегося внутри куба.
7. Измените разрешение при разработке и проверьте размеры PPM.
8. Отправьте текстовый файл с расширением `.png` и убедитесь, что сервер его отклоняет.

## Частые проблемы

- **Cargo/npm не могут получить зависимости:** при первой установке нужен доступ к реестрам пакетов.
- **Порт 3000 занят:** остановите процесс, использующий порт, или измените адрес в `src/api/mod.rs` и прокси Vite.
- **AI-генерация не работает:** проверьте установлен ли TripoSR, Python-окружение, `TRIPOSR_DIR`/`TRIPOSR_PYTHON` и сообщение сервера.
- **Файл отклонён:** нужен действительный JPEG/PNG размером не больше 10 МБ и 25 мегапикселей.
- **Пустой просмотрщик:** проверьте поддержку WebGL и консоль браузера. Демо-примитивы не требуют AI.
- **PPM не совпадает с предпросмотром Three.js:** браузер показывает GLB и интерактивную сцену, Rust рендерит выбранный встроенный набор примитивов.
