# RT Studio — запуск и руководство

## Что нужно

- Rust и Cargo.
- Node.js 20+ и npm.
- Браузер с поддержкой WebGL.
- Для генерации нужен TripoSR, Python 3.8+ и PyTorch. Ключ и платные API-вызовы не нужны. Без модели работают просмотр демо-сцены, редактор и Rust-рендер.

## Первый запуск

Откройте терминал в корне проекта (`/home/student/rt`) и соберите интерфейс:

```bash
cd frontend
npm install --ignore-scripts
npm run build
cd ..
```

Установите локальную модель TripoSR и Python-зависимости:

```bash
bash scripts/setup-local-ai.sh
```

Установка требует интернет и несколько гигабайт свободного места. Скрипт выберет PyTorch для NVIDIA GPU, если она найдена, иначе CPU-сборку. Веса модели скачаются при первом запуске генерации. Папка `vendor/TripoSR` и виртуальное окружение `.venv-triposr` исключены из Git.

Запустите сервер из корня проекта:

```bash
cargo run
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Сервер автоматически читает `.env`. Если ключ не задан, остальные функции доступны, а статус интерфейса покажет, что генерация AI выключена.

## Режим разработки

В первом терминале из корня проекта запустите backend: `cargo run`. Во втором терминале:

```bash
cd frontend
npm run dev
```

Перейдите по адресу Vite, обычно [http://127.0.0.1:5173](http://127.0.0.1:5173). `/api` и `/docs` проксируются на Rust-сервер `127.0.0.1:3000`.

## Как построить 3D-модель

1. Выполните установку TripoSR из предыдущего раздела.
2. Загрузите чёткое изображение одного предмета в формате JPEG или PNG (до 10 МБ и 25 мегапикселей).
3. Нажмите **Create 3D model**. Сервер проверит изображение и запустит TripoSR локально.
4. Дождитесь статуса завершения. Модель GLB появится в окне, а ссылка скачает файл.

Генерация не использует платный API. Первичная установка и загрузка весов требуют интернет-соединения; после установки модель запускается локально. Без NVIDIA-видеокарты она работает через CPU и может быть медленной. Одно фото не содержит информации о скрытых сторонах, поэтому результат приблизительный.

## Проверка работы

- Состояние backend: `http://127.0.0.1:3000/api/health`.
- Собрать интерфейс: `cd frontend && npm run build`.
- Запустить проверки Rust: `cargo test`.
- Сгенерировать четыре статичные PPM-сцены: `cargo run -- render-scenes`.
- Интерактивный рендер доступен в панели **Render**; он рендерит встроенные сцены, а не импортированный GLB.

## Если что-то не работает

- **Страница не открывается:** проверьте вывод `cargo run`; порт 3000 должен быть свободен. Для production сначала выполните `npm run build`.
- **Vite показывает страницу, но API недоступно:** backend должен работать в отдельном терминале на порту 3000.
- **Генерация недоступна:** выполните `bash scripts/setup-local-ai.sh`; затем проверьте `TRIPOSR_DIR` и `TRIPOSR_PYTHON` в `.env`.
- **`NameResolutionError`, `Failed to resolve` или ошибка `huggingface.co`:** TripoSR не смог скачать веса модели. Проверьте интернет и DNS, затем повторите генерацию. Первое скачивание требует доступа к Hugging Face; после успешной загрузки веса хранятся в локальном кэше. Если сеть учебного заведения блокирует Hugging Face, скачайте модель через другую сеть и перенесите кэш Hugging Face на компьютер проекта.
- **Предварительная загрузка модели:** подключитесь к сети с доступом к Hugging Face и выполните `bash scripts/download-ai-model.sh`. Скрипт загрузит веса TripoSR и конфигурацию DINO в `~/.cache/huggingface`. Если загружаете на другом компьютере, перенесите папку `~/.cache/huggingface` в домашнюю папку пользователя, запускающего `cargo run`.
- **Сервер не принимает картинку:** используйте настоящий JPEG/PNG; имя файла само по себе не определяет формат.
- **Просмотрщик пустой:** проверьте WebGL, консоль браузера и наличие демонстрационного объекта `DEMO`.
- **Ошибка сборки:** убедитесь, что команды запускаются в нужной папке и зависимости установлены.
